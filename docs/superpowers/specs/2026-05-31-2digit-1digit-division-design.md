# 設計: 2ケタ ÷ 1ケタ 整数わり算ラボ

作成日: 2026-05-31
対象ファイル: `index.html`（「わり算ラボ」/ 単一ファイル・IIFE）

## 目的

既存の「わり算ラボ」に **整数 ÷ 整数（2ケタ ÷ 1ケタ）** のモードを追加する。
わり算の **筆算がはじめての子** でも「なぜそうなるか」がわかるように、具体物で
分ける体験 → 筆算 → たしかめ算、という流れで段階的に理解させる。

## スコープ

- わられる数: 2ケタ（10〜99）
- わる数: 1ケタ（2〜9）
- **商は必ず2ケタ**（十の位に必ず商が立つ）。商の十の位が 0 になるケース
  （例: 12÷4=3、48÷6=8）は初回学習では出さない。手順がきれいに一巡するため。
- あまり: 「わりきれる」を先に、慣れたら「あまりあり」も出す。
- 既存3モード（小数÷整数 / 整数÷小数 / 小数÷小数）の挙動は変更しない。

### スコープ外（YAGNI）

- 3ケタ以上、2ケタ÷2ケタ。
- 商の十の位が立たないケースの専用指導。
- 既存モードのリファクタ（今回の追加に必要な範囲を超える変更はしない）。

## 全体構成

ホームに4つ目のボタン「➗ 2ケタ ÷ 1ケタ ラボ」を追加する。
押すと小メニューが開き、2つの編から選ぶ:

| 編 | タイマー | 筆算スタイル | むずかしさ |
|----|----------|--------------|------------|
| れんしゅう（やさしい） | 無し | A型（フル4ステップ・ガイド） | わりきれる → あまり |
| ちょうせん（ゲーム） | あり（バクハツ演出） | B型（商の数字えらび） | わりきれる → あまり |

各編は既存と同じく10問1セット。前半は「わりきれる」、後半に「あまり」を混ぜる
難易度ランプ（既存 `buildPlan()` と同じ思想）。わる数も前半 2〜5 中心、
後半 6〜9 を混ぜる。

## 1問の流れ（3フェーズ維持）

例: 48 ÷ 3 = 16

### フェーズ① 分ける（10のたば ＆ ばら）

- わられる数を「10のたば × 十の位の数」＋「ばら × 一の位の数」で表示
  （48 → たば4本 ＋ ばら8本）。
- **十の位を分ける**: たばを人数（わる数）で同じだけ配る。
  4本を3人へ → 1本ずつ、1本あまる。
- **くずす（＝筆算の「おろす」の正体）**: あまったたば1本を「ばら10本」に
  くずす。ばらは 10 + 8 = 18 本になる。
- **一の位を分ける**: ばら18本を3人へ → 6本ずつ。
- 結果: 1人ぶん ＝ たば1 ＋ ばら6 ＝ 16。
- あまりありの場合: 一の位を配ったあとに残るばらが「あまり」。
- 操作: タップ/スライダーで配る。正しく分けられたら② へ自動遷移。

### フェーズ② 筆算

商は十の位 → 一の位の順に求める。各位で「たてる → かける → ひく → おろす」。

- **A型（れんしゅう）— フル4ステップ・ガイド**
  - **たてる**: その位の商の数字を選ぶ（4択）。← 子どもが考える中心。
  - **かける**: ボタンを押すと「商 × わる数」の積が下に書かれる（アニメで出現）。
  - **ひく**: ボタンを押すと引き算の結果が書かれる。
  - **おろす**: ボタンを押すと次の位の数字が下りてくる（① の「くずす」と対応）。
  - 順番をまちがえて押したら、シェイク＋「つぎは ◯◯ だよ」とやさしく案内。
  - 最後の位で「ひく」の結果が 0 → わりきれた、0以外 → それがあまり。
- **B型（ちょうせん）— 商の数字えらび**
  - 既存の筆算と同様、各位の商だけを4択で選ぶ。かける/ひくは下に文章で自動表示。
  - 既存 `longDivision()` ＋ `renderLong()` 系の整数版を流用。

### フェーズ③ たしかめ算

- 既存ロジックを再利用。「？ ÷ わる数 = 商（あまり R）」を見せ、
  「商 × わる数（＋あまり）」を選ばせて、もとのわられる数に戻ることを確認。
- 既存 `goCheck()` / `pickCheck()` は被除数 `current.a`、商 `current.ans`、
  わる数 `current.b`、あまり `current.rem` で動くため、整数値を入れれば流用可能。
  選択肢の誤答生成（小数前提の delta）は整数用に調整する。

## データモデル（問題オブジェクト）

既存 `gen()` が返す `current` 形に合わせ、mode=3 用の分岐を追加する。

```
current = {
  mode: 3,
  hasRem: bool,
  a: 48,        // わられる数（整数）
  b: 3,         // わる数（整数）
  ans: 16,      // 商（整数・2ケタ）
  rem: 0,       // あまり
  tens: 4,      // 十の位（たば本数）
  ones: 8,      // 一の位（ばら本数）
  variant: 'A' | 'B',   // 筆算スタイル（れんしゅう=A / ちょうせん=B）
  story, prob, beakerInstr(→分けるinstr), hint   // 既存と同じ表示用
}
```

問題生成: わる数 b と 2ケタの商 q（10〜）を選び、a = b×q（+ あまり r, 0<r<b）。
a ≤ 99 を満たす範囲でプール化（既存 MODE0/MODE0R と同様の事前生成）。

## コンポーネント分割（既存 IIFE 内に追加）

| 単位 | 役割 | 依存 |
|------|------|------|
| `genInt(withRem, variant, forceB)` | mode=3 の問題生成 | 問題プール |
| `buildBundles()` | ① たば&ばら の描画と配る操作 | `current` |
| `checkBundles()` | ① の正誤判定 → ②へ | `current`, beaker判定に相当 |
| `render4Step()` | ② A型 筆算の描画とステップ進行 | `current`, `longDivision()` |
| `renderLongInt()` | ② B型 筆算（既存 renderLong の整数版/流用） | `longDivision()` |
| 既存 `goCheck`/`pickCheck` | ③ たしかめ算（整数対応に微調整） | `current` |
| 既存 timer/HUD/result | 共通インフラ（ちょうせん編のみタイマー有効） | — |

分岐方針: `current.mode===3` の枝を `buildBeakers()`/`goCalc()`/`loadQuestion()`
等に足す。① と ② の中身は専用関数に切り出し、本体は薄いディスパッチにする。
タイマーは編によって `TIME_LIMIT` を `Infinity`（れんしゅう）/ 既存秒数（ちょうせん）
で切り替える。れんしゅう編ではバクハツ・タイムピルを非表示にする。

## エラー処理・エッジケース

- 商の十の位が 0 になる組み合わせは生成プールから除外（スコープ参照）。
- ① で配りすぎ/足りないときは既存ビーカーと同様にシェイク＋メッセージで再操作。
- ② A型でステップ順を誤ったら処理を進めず案内のみ。
- たしかめ算の誤答選択肢は整数 delta（±1, ±2, ±10, ±b 等）で生成し、重複・
  負数・正解との衝突を除外。

## テスト/受け入れ確認

ブラウザで以下を手動確認する:

1. ホームに新ボタンが出て、小メニューから2編に入れる。既存3モードは無変更で動く。
2. れんしゅう: わりきれ問題（例 48÷3）で ①たば&ばら → ②A型4ステップ →
   ③たしかめ で 16 に到達。タイマー無し・バクハツ無し。
3. れんしゅう後半: あまり問題（例 53÷4=13あまり1）で、一の位の配りで
   ばらが1本あまり、② で最終ひき算が1、たしかめが 13×4+1=53。
4. ちょうせん: タイマー作動、時間切れでバクハツ→同じ問題から再開。B型筆算で商を選ぶ。
5. 商が必ず2ケタになっている（生成プールの確認）。
6. たしかめ算の選択肢に正解が1つだけ含まれ、整数で表示される。
